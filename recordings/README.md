# Shared mission catalog

Recordings published in this catalog sync automatically into everyone's SmallVerse Recorder library. No sign-in is required to receive them. New versions must be reviewed locally before replay.

## Contribute from the extension

1. Open **Review / Share** and inspect typed text, visual targets, mission text and space URLs. Confirm the start/finish timer markers and include setup instructions.
2. Check the review box and click **Share to GitHub**. This downloads the reviewed JSON and opens a prefilled GitHub issue.
3. Sign in if needed, **attach the JSON to the issue**, and submit. Mark it tested only if you replayed that version successfully.
4. A maintainer reviews and adds it to the catalog. It reaches other installations after that commit is merged to `main` and their next sync runs.

The button does not directly upload or publish files, bypass repository permissions, or require a GitHub token inside the extension. Anyone with a GitHub account can submit; maintainers control publication.

## Maintainer: publish a reviewed submission

Download and inspect the submitted JSON, especially typed text, visual patches, space URLs, timing markers, prerequisites and notes. Do not run unreviewed mission inputs on your account.

From the repository root:

```sh
npm run add-recording -- --file /path/mission.json --slug easter-island --author GitHubName --revision 1
npm run check
npm test
```

The command adds `recordings/easter-island.json` and an entry in `recordings/index.json`, with a SHA-256 checksum. Use `--replace --revision 2` for an intentional update to an existing slug. Add `--description "..."` for a short catalog description. Review the diff, commit, and push or merge to `main`.

Catalog entries look like:

```json
{
  "name": "Easter Island",
  "path": "recordings/easter-island.json",
  "author": "GitHubName",
  "revision": "1",
  "sha256": "<64 lowercase hex characters generated by the helper>",
  "description": "Community recording; read its starting instructions before replay."
}
```

The catalog is a JSON array. Legacy entries without checksums still sync but must be re-downloaded to detect updates. Prefer the helper so author/revision/checksum are included. CI validates timing, filenames, schema and checksums; it cannot verify gameplay.

## What everyone receives

Sync runs on opening the extension/library, on install/update, on Chrome startup, approximately every 30 minutes, and on **Sync now**. Automatic open checks have a one-minute cooldown; active recording/replay defers new syncs. Cached files remain available offline. GitHub caches may briefly delay new versions.

A shared update requires new local review before replay. Local edits are saved as personal copies and are never overwritten. Removing a catalog entry marks its cached copies Withdrawn and excludes them from replay selection; a user can still explicitly review and save a personal copy.

This catalog is public. Passwords, credentials and private conversations must not be included. The library begins empty until actual mission recordings are contributed.
